# Modernisation Plan for the macOS Inform App

Started November 2026, on the `extensions` branch. This is a living document: update it as phases complete or decisions change.

## Goals, in order

1. Compile cleanly and work with the latest Xcode.
2. Merge in the latest versions of the Zoom and CocoaGlk submodules.
3. Fix existing bugs.
4. Find and fix new bugs.
5. Convert the source to Swift, in managed stages.
6. Add new features.

## Starting point (November 2026)

- Xcode 26.3 (macOS SDK 26.2) on macOS 15.7. A clean, unsigned Debug build succeeds with 0 errors and 711 unique warnings (`documentation/warnings_baseline.txt`).
    - 519 of those are `-Wdeclaration-after-statement`, which appears because the Inform target uses `-Weverything` and every new Clang adds warnings.
    - Others worth fixing: 80 single-bit bitfield conversions in `IFInform6Highlighter.m` (assigning YES to a 1-bit field gives -1, possibly a real bug), format-string mismatches, missing `default:` labels, and a deprecated `endSheet` call in `IFNewThemeWindow.swift`.
    - In the submodules: deprecated `NSConnection`/`NSDistantObject` (Distributed Objects), WebKit 1 `WebDataSource`, `NSReadPixel`, `NSUnarchiver`, `mktemp`.
- The app is about 42k lines of Objective-C (117 `.m` files) and 1k lines of Swift (21 files).
- The project file is at Xcode 13.1 level (`LastUpgradeCheck = 1310`), deployment target macOS 10.14, Swift 5.0.
- Zoom is 190 commits behind `MaddTheSane/zoom` `madds`; CocoaGlk is 16 behind `MaddTheSane/CocoaGlk` `madds`. Zoom records CocoaGlk at `eb26b55`, but `4b31951` is checked out.
- The local change to CocoaGlk's `GlkClient/glk_unicode.m` is superseded by upstream commit `622461f` (fixes issue #41).
- InformQL is a `.qlgenerator` plugin. macOS 15 is believed to no longer load these (not yet verified). Upstream Zoom now has Swift Quick Look extensions (`ZoomNewSaveQL`, `ZoomThumbnailer`) that show a replacement pattern.
- RegexKitLite (uses the deprecated `OSSpinLock`) is used in three files.
- There were no tests.

## Ground rules

- **Signing stays manual.** The app runs separately signed command-line tools and interpreter processes, so Xcode's "Update to recommended settings" is reviewed change by change, never accepted wholesale.
- **Review is local.** Work happens on local branches as small commits for review; nothing is pushed without asking.
- **Submodules track MaddTheSane's `madds` branches.** Fixes we need go upstream as pull requests; fork only if a patch is Inform-specific and won't be accepted.
- **Swift conversion is one-to-one.** Keep AppKit and the xibs. A commit either moves logic or translates it, never both. SwiftUI is undecided.
- **The StagingArea binaries stay in git** as they are.

### Phase 5 – Swift, and separating logic from UI (goal 5)

- First add nullability and generics annotations to the Objective-C headers.
    - The rule: everything is non-null unless the implementation can return or accept nil, including when a file or resource might not be found or a string might not parse. Callers that pass nil count too. Each batch is checked with a build, the unit tests, and the analyser's nullability checks.
    - Order, bottom-up: utilities and categories; then the model (skein, syntax, settings, extensions, project and compiler); then the controllers, pages and views.
    - [x] Utilities and categories (4 November 2026, 06335e3a): `IFUtility`, the `NSString`, `NSAttributedString` and `NSBundle` categories, `IFViewAnimator`, `IFNotifyingWindow` and `IFSemVer`. Found on the way: a yes/no alert with no window (Delete Theme, overwriting a project) was run as a modal and then begun again as a sheet, so it could ask twice; it now asks once (ef5d7bf3, checked on screen with Delete Theme). Also, `attributedStringWithFontSize:` is unused.
    - [x] Skein model (4 November 2026, 6c700bae): `IFSkein`, `IFSkeinItem` and `IFDiffer`. Found on the way: a knot dragged to a new place in the skein lost its blessed (ideal) transcript, and so did every knot below it, because the drag copy didn't archive it; it now keeps it (0fe4d10c, with a unit test). The skein views go with the other views.
    - [x] Syntax (4 November 2026, 1ca60068): `IFSyntaxManager`, `IFSyntaxData`, `IFSyntaxTypes`, `IFSyntaxStyles`, `IFIntelFile`, `IFIntelSymbol` and the Inform 7 comment helpers. Found on the way: Renumber Sections read before the start of its line table for the first section in each chapter (since the move to 64-bit), so that section's new number depended on whatever was in memory; it now counts from 1 (d81b528f, with a unit test that fails under Address Sanitizer without the fix). Also, the `IFDerivativeStorage` protocol is unused.
    - [x] Settings (4 November 2026, c156901e): `IFCompilerSettings`, `IFSetting` and its panes, `IFSettingsController` and `IFCollapsableView`. Found on the way: opening a project whose `Settings.plist` (or old-style `Settings` file) is a folder raised an exception, because `NSFileWrapper` only gives the contents of a file; such a project now opens with the default settings (2155e48c, with a unit test).
    - [x] Extensions (4 November 2026, cacf21de): `IFExtensionsManager` (with `IFExtensionInfo` and `IFExtensionDownload`) and `IFNewExtensionsManager`. - Classes that are already separate from the UI: add tests, then convert one-to-one, bottom-up (utilities and categories, then model classes).

## Decisions

- Branches (decided 3 November 2026). `extensions` is 63 commits ahead of `master`, which hasn't moved since April 2023, and the work branches come off `extensions`. But `master` is the default branch on GitHub, so outside pull requests are made against it (TobyLobster/Inform#52, #53, #54), while #51 and this work are against `extensions`. Merging one into `master` would stop `master` being a fast-forward, so #52, #53 and #54 were retargeted to `extensions` (3 November 2026). #52 merges cleanly (this work has the same change, cherry-picked as 9446c465). #54 then conflicts in `IFAppDelegate.h` (`extensions` removed the `showInspectors:` declaration beside it; keep only `showAbout:`), and #53 merges cleanly but will conflict in `configure.py` with this work (keep `hardened_runtime`; drop `sign_child_projects` and the submodule loop). Once the phase branches are merged into `extensions`, move `master` up to it (a fast-forward: `master` has nothing `extensions` lacks) and use `master` from then on. The 1.82 releases stay on `r1.82` and their tags. Done on 4 November 2026: `master` and `extensions` are both at 2f9525d6, with phases 0 to 2 and #51 to #54, and new work branches come off `master`.
- Branching after Phase 2 (decided 4 November 2026). Phases 0 to 2 were long-lived branches stacked on each other and landed together, 86 commits at once, and outside pull requests conflicted with work that had waited days to land. From Phase 1b on, work goes on short branches off `master`, each landed as soon as it's reviewed. Review stays local, and the maintainer pushes.
    - Phase 1b: on the Inform side, one branch per submodule update once MaddTheSane merges our pull requests, carrying the warnings baseline update. Another for per-file warning settings on the generated parsers.
    - Phase 3: one branch per issue (`fix/41-title-case-crash`). "Fixes #41" in a commit closes the issue when it reaches `master`, so it's only used for complete fixes (#46 and #49 were closed that way).
    - Phase 4: one branch per finding, or per group of tests.
    - Phase 5: one branch per class or small group of classes, with commits that move logic kept separate from those that translate it. The nullability and generics annotations go first, on their own branch.
    - Phase 6: one longer-lived branch per feature (the Quick Look extensions, XPC), with `master` merged into it regularly.
    - Landing: a branch of one or two commits is fast-forwarded onto `master`, after a rebase if `master` has moved. A larger piece (a Swift conversion, a feature) gets a `--no-ff` merge, so it can be found or reverted as a whole.
    - `extensions` is retired at 2f9525d6, the same as `master`, with no pull requests against it. `r1.82` stays for any 1.82 fixes.
